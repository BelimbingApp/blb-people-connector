# Reconciliation operator runbook

Open the connection's reconciliation page as an operator with `people-connector.identity.manage` and access to that connection's company in the current tenant. The page lists open issues, their safe diagnostic details and available decisions. A missing or inaccessible connection/issue cannot be operated on. See [operator guards](../../Connector/Tests/Feature/OperatorActionGuardsTest.php) and the [page implementation](../../Connector/Livewire/Reconciliation/Index.php).

Before resolving an issue, inspect the provider evidence and record the review reference or resolution note. **Resolve with note** closes the queue item and records the note in the semantic action log. It does not retry a command, import a page, repair an identity or perform privacy erasure. Reviewed merge and remap are separate actions that change identity state and close the issue atomically. See [ReconciliationReviewService](../../Connector/Services/ReconciliationReviewService.php) and [page tests](../../Connector/Tests/Feature/ReconciliationPageTest.php); the operator surface landed in [#107](https://github.com/BelimbingApp/blb-people-connector/pull/107).

## Issue types and decisions

| Issue kind | What raised it | Available decision and its effect | Origin and evidence |
|---|---|---|---|
| `sync_conflict` | A workforce upsert or deactivation hit a handled projection, identity, company-move, missing-record or history refusal; the issue identifies the external record and a safe reason code. | Inspect the conflict. Where an external record is identified, the page offers a reviewed remap to a distinct external ID; it changes the identity mapping and closes the issue. Generic resolution only closes it. Neither reapplies the refused record. | [#72](https://github.com/BelimbingApp/blb-people-connector/pull/72); [WorkforceSyncRunnerTest](../../Connector/Tests/Feature/WorkforceSyncRunnerTest.php). |
| `sync_merge_requested` | The provider change feed requests merging a superseded external identity into a survivor. | **Apply reviewed merge** requires a review reference and surviving external ID in the queued evidence. It merges the identities and closes the issue; it is not a feed retry. A legacy row missing the survivor cannot use that action. Generic resolution does not merge. | [#72](https://github.com/BelimbingApp/blb-people-connector/pull/72), [#107](https://github.com/BelimbingApp/blb-people-connector/pull/107); [ReconciliationPageTest](../../Connector/Tests/Feature/ReconciliationPageTest.php). |
| `sync_empty_bootstrap` | Bootstrap completed without any records; no successful checkpoint is advanced by that empty result. | Confirm whether the provider is actually empty or misconfigured, correct the source and deliberately arrange another bootstrap. The page offers generic resolution; it cannot create workforce records or start bootstrap. | [#72](https://github.com/BelimbingApp/blb-people-connector/pull/72); [WorkforceSyncRunnerTest](../../Connector/Tests/Feature/WorkforceSyncRunnerTest.php). |
| `sync_feed_refused` | A feed pass saw conflicts but effected no records, deactivations, reactivations or queued merges. | Investigate the record conflicts before another pass. Generic resolution does not advance the checkpoint. When the configured failed-attempt threshold parks the page, the runner closes this feed-refused issue and raises the dead-letter issue. | [#72](https://github.com/BelimbingApp/blb-people-connector/pull/72), [#176](https://github.com/BelimbingApp/blb-people-connector/pull/176); [WorkforceSyncRunnerTest](../../Connector/Tests/Feature/WorkforceSyncRunnerTest.php), [DeadLetterTest](../../Connector/Tests/Feature/DeadLetterTest.php). |
| `sync_unknown_outcome` | Command reconciliation still cannot determine whether a provider command took effect. The issue key is the command's idempotency key. | Check the provider directly, then **Confirm command outcome** with a review reference and the delivered/not-delivered selection. This records the conclusion and closes the issue; it never resends. Generic resolution likewise does not settle delivery or resend. Any resend remains a separate deliberate operation. | [#151](https://github.com/BelimbingApp/blb-people-connector/pull/151); [UnknownOutcomeOperatorTest](../../Connector/Tests/Feature/UnknownOutcomeOperatorTest.php), [UnknownOutcomeResolutionTest](../../Connector/Tests/Feature/UnknownOutcomeResolutionTest.php). |
| `sync_stale` | Freshness review finds a breached policy for an active connection, including a connection that never completed sync. | Investigate provider/scheduler health. Generic resolution does not make projections fresh. Freshness review clears open stale alerts when the connection becomes fresh or inactive. | [#155](https://github.com/BelimbingApp/blb-people-connector/pull/155); [SyncFreshnessAlertTest](../../Connector/Tests/Feature/SyncFreshnessAlertTest.php). |
| `sync_dead_letter` | An entirely refused feed page reached the configured consecutive-failure limit (default three). The runner parks a hash and safe reason/count, then advances the checkpoint past that page. | The page currently offers generic resolution, not a requeue button. The application service `DeadLetterService::requeue` separately requires a review reference, closes the parked issue and clears failed attempts; it does not read the page or rewind the checkpoint. Deliberate `WorkforceSyncRunner::replay` from the earlier checkpoint is still needed. A replayed page that fails and is parked again reopens its existing issue. | [#176](https://github.com/BelimbingApp/blb-people-connector/pull/176), replay [#160](https://github.com/BelimbingApp/blb-people-connector/pull/160); [DeadLetterTest](../../Connector/Tests/Feature/DeadLetterTest.php), [DeadLetterService](../../Connector/Services/DeadLetterService.php). |

The current seven kinds are declared by [WorkforceSyncRunner](../../Connector/Services/WorkforceSyncRunner.php), [UnknownOutcomeReporter](../../Connector/Services/UnknownOutcomeReporter.php), and [SyncFreshnessAlerter](../../Connector/Services/SyncFreshnessAlerter.php). The issue store also accepts caller-supplied kinds; this table covers the kinds emitted by the current production services, not every possible future kind.

## Privacy tombstone refusals

Privacy erasure refusal is an exception, **not an eighth reconciliation issue kind**. Identity erasure refuses while an open reconciliation issue references that identity. Review that issue on its merits before retrying the authorized erasure operation; closing a row does not itself erase anything. A foreign connection or unknown provider identity also refuses; company-wide erasure uses `eraseCompany`, not identity erasure. The reconciliation page has no privacy-erasure action. These boundaries come from [#152](https://github.com/BelimbingApp/blb-people-connector/pull/152), [PrivacyDeletionService](../../Connector/Services/PrivacyDeletionService.php) and [IdentityPrivacyDeletionTest](../../Connector/Tests/Feature/IdentityPrivacyDeletionTest.php).

Erasure tombstones connector projection fields and redacts snapshots while preserving People-owned history; queue resolution must not be presented as undoing or restoring that erasure. Company-scope behavior originates in [#60](https://github.com/BelimbingApp/blb-people-connector/pull/60), with evidence in [PrivacyDeletionTest](../../Connector/Tests/Feature/PrivacyDeletionTest.php). Keep provider payloads and credentials out of resolution notes and review references; use attributable references to the governed evidence, following [diagnostic privacy](../contracts/diagnostic-privacy.md).
